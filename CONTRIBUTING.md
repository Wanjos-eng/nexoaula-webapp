# Como contribuir

## Regra principal

Ninguém trabalha diretamente na `main`. Toda mudança deve ser desenvolvida em uma branch e submetida por Pull Request.

## Padrões de branch

Use nomes curtos e descritivos:

- `feat/descricao`
- `fix/descricao`
- `docs/descricao`
- `refactor/descricao`
- `chore/descricao`

## Commits

- Faça commits pequenos, coesos e descritivos.
- Não inclua credenciais, tokens, senhas ou arquivos `.env`.
- Separe alterações sem relação em commits e Pull Requests diferentes.

## Pull Requests

- Todo trabalho deve ser submetido por Pull Request.
- O Pull Request deve referenciar a história, tarefa ou issue correspondente.
- Preencha o template, explique como testar e inclua evidências quando aplicável.
- O autor não deve mesclar o próprio Pull Request sem a revisão exigida.
- Resolva conflitos na branch do autor, sem force push na `main` e sem reescrever o histórico compartilhado.
- Resolva todas as conversas antes do merge.
- O método de merge adotado é Squash merge.
